# 新增与维护技能

## 何时使用

- 当前任务形成了后续同类任务都应遵守的流程、约束或安全规则。
- 代码、工作流、测试或工具能力变化，导致现有 skill 过期、不准确或不可执行。
- 多个 skill 存在重复、冲突或职责边界不清。
- 用户明确要求新增、整理或维护 skill。

一次性处理步骤、临时调试信息和可直接从代码读出的实现细节，不写入 skill。

## 决策顺序

1. 搜索 `.agents/skills`，确认是否已有职责匹配的 skill。
2. 有匹配项时优先维护现有 skill，并合并重复或冲突规则。
3. 没有合适归属，且规则会在后续任务中复用时，才新增 skill。
4. 新 skill 只承担一个清晰职责；名称使用小写连字符，目录名、frontmatter `name` 和调用名保持一致。

## 编写要求

- 先读取相关代码、工作流、测试和已有 skill，再修改描述；不得凭假设编写项目规则。
- `description` 应说明触发场景和职责，便于任务自动匹配，正文不重复解释同一规则。
- 使用明确、可执行的步骤，删除无效、过期和仅提供背景的信息。
- 通用规则放入通用 skill；项目特有行为放入对应项目 skill，并通过引用避免复制整段规则。
- 不扩大用户请求的功能范围，不覆盖无关改动，不在 skill 中记录凭据、测试账号或其他敏感信息。

## 验证

1. 重读完整文件，确认 frontmatter 有效、名称一致且没有重复规则。
2. 对照当前代码和工作流核验涉及的命令、路径、输入格式与行为。
3. 检查 diff 和工作区状态，确认仅修改本次相关文件且未包含敏感信息。
4. 运行项目适用的格式检查、测试和构建；仅修改文档时也应执行可用的最低成本校验。
